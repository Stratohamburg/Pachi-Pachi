# 界面布局与交互规范 (Interface & UX Design)

## 0. 版本范围说明 (Release Scope)
本文件同时记录首发 MVP 与后续迭代方向。除非特别注明为“后续阶段”，默认要求均以**单人离线 MVP** 为准。

* **首发 MVP 必须包含：** 局内 HUD、右下角竖向手柄、三选一遗物弹层、基础大厅导航、图鉴/抽卡的功能页、设置页。
* **后续阶段再评估：** 3D/2.5D 大厅漫游、重社交展示位、排行榜面板、超长抽卡演出、需要在线数据支撑的活动入口。

## 1. 核心操作区：右下角竖向手柄 (Right-Side Vertical Launcher)
基于多次可用性验证，柏青哥式微操最重要的一环在于“防遮挡”与“精准刻度控制”。
* **区域位置：** 无论是移动竖屏还是PC横屏，操作手柄区统一永久锚定于**机台 Canvas 区域的右下角（约占机台宽度的15%，高度的30%-40%）**，非整个浏览器视口的边界，以保证宽屏下操作的视觉连贯性。
* **滑动操作 (Swipe to Pull)：** 
  * 交互形式为一个带有物理弹簧反馈的**竖向长条槽**，内部包含一个拉杆推钮。
  * 玩家拖拽推钮向下移动进行**拉紧（蓄力）**。越往下拉，阻尼感（或震动反馈）越强。
  * **松手发射 (Release to Fire)：** 松开手指/鼠标即进行弹射。
* **刻度盲打辅助 (Scale Guides)：** 绝对禁止使用发射后的虚线轨迹。轨道两侧必须带有极其精细且带有短杠的刻度线刻度尺，满足玩家多次试错后的微操背板与手感记忆需求。

## 2. 主屏视野 (HUD - Heads Up Display)
游玩区应当尽量保持沉浸感，不让按钮喧宾夺主。
* **积分与连击看板 (Score & Combo)：** 
  * 半透明悬浮设计，置于机台画面上方或左上角。高频碰撞时数字随之跳动放大。
* **状态信息栏 (Status Bar)：** 
  * 顶部居中或左上角常驻，首发展示软货币、本局剩余可用“英雄弹珠”数量（HP）与暂停入口；在线入口属于后续阶段。
* **Fever槽位区：** 
  * 在机台大奖孔的上方或屏幕左侧，用霓虹或发光灯管的形式拼成一根能量管。单球有效碰撞持续充能，高分机关与大奖槽给予额外充能表现。

## 3. 面板与菜单交互系统 (Menu Flow)
除了局内 HUD，层级界面使用轻量级的弹出层(Pop-ups)。
* **局内商店与构筑层 (Roguelite Shop & Relic UI)：**
  * 在触发“三选一”遗物时，画面背景进行强烈的暗态模糊化 (Blur)，屏幕中间清晰弹出三张对应 Buff 的卡牌或图标组件，带有粗体简短的机制描述。
* **局外大厅界 (Main Lobby)：**
  * **首发 MVP：** 采用轻量 2D 页面式大厅，明确提供 `Play`、`Gacha`、`Meta Tree`、`Settings` 四个入口。
  * **后续阶段：** 可升级为复古或赛博游戏机厅的 3D/2.5D 透视场景，将入口融入场景点击物中。

### 3.1 首发页面清单 (MVP Page Inventory)
首发版本的 DOM UI 建议固定为以下页面与弹层，避免后续开发过程中无序扩张：

* `LobbyPage`：大厅导航与局外入口页。
* `BattlePage`：局内常驻 HUD 与手柄页（包含机关放置UI交互）。
* `ResultPage`：本局结算页。
* `GachaPage`：抽卡功能页。
* `GalleryPage`：英雄弹珠图鉴页。
* `MetaTreePage`：局外天赋树页。
* `SettingsPage`：画质、音量、输入偏好设置页。

### 3.2 BattlePage 交互状态映射
`BattlePage` 至少需要覆盖以下交互状态，避免玩法状态和 UI 状态各自为政：

* **Ready 状态：** 展示关卡标题、目标分数和剩余球数，手柄禁用。
* **Aiming 状态：** 手波次标题、目标分数和当前阶段可用球数，手柄禁用。
* **Placement 状态：** 获得新的肉鸽机关时激活，允许玩家在机台的规定区域内点击/拖拽放置额外的钉子、弹力柱等道具。
* **Aiming 状态：** 手柄激活，玩家**唯一操作**为上下拉动控制力度。刻度线增强，允许玩家输入确切的力度偏好。
* **Flying 状态：** 手柄锁定，HUD 重点展示 Combo、Fever 充能与碰撞反馈。
* **RelicChoiceOverlay 状态：** 暂停局内物理表现，弹出三选一卡牌（可选新弹珠或新机关道具）。
* **Settlement 状态：** 展示本球/本波次结算、倍率变化、是否继续下一波

### 3.3 页面级线框说明 (MVP Wireframes)

#### `LobbyPage`
* **线框结构：** 顶部为玩家资源条，中部为主入口卡片区，底部为次级导航与最近进度摘要。
* **必备组件：** 玩家名片、软货币与体力展示、`Play` 主按钮、`Gacha` / `Meta Tree` / `Garage` / `Settings` 入口卡片、最近一次 Run 结果摘要。
* **空状态：** 首次进入且无历史存档时，中部显示“开始第一次 Run”的单一主按钮，并展示极简新手提示。
* **错误状态：** 若本地存档读取失败，页面保留基础入口，但顶部展示“本地存档异常”的警示条，并提供 `重试读取` 与 `重置本地数据` 两个恢复操作。
#### `BattlePage`
* **线框结构：** 中央为 Pixi 机台画布，顶部为 HUD，右下为手柄操作区。PC横屏时左右侧预留道具库存、本局弹珠列表面板；移动端竖屏时通过顶部下拉抽屉或详情面板展示。
* **必备组件：** 分数看板、波次目标、Combo、Fever 条、剩余球数、当前弹珠切换按钮、暂停按钮、布置模式切换（如有）、右下竖向手柄、临时飘字层。
* **空状态：** 若关卡资源仍在载入，则画布区显示加载占位和当前波次名，手柄保持禁用。
* **空状态：** 若关卡资源仍在载入，则画布区显示加载占位和当前关卡名，手柄保持禁用；若本局尚未获得遗物，则遗物区显示“尚未获得遗物”的占位说明。
* **错误状态：** 若关卡加载或结算写回失败，立即冻结手柄输入，展示覆盖式错误弹层，并提供 `重试本关` 与 `返回大厅` 操作。

#### `ResultPage`
* **线框结构：** 顶部为评级与标题，中部为奖励和成长变化，底部为继续操作区。
* **必备组件：** 本局总分、推进层数、评级徽章、软货币收益、记忆碎片收益、解锁或升级变化卡片、`再来一局` / `返回大厅` / `前往养成` 按钮。
* **空状态：** 若本局未产生新解锁或升级，中部仍需显示基础收益，同时以弱化提示说明“本局没有新的解锁变化”。
* **错误状态：** 若结算奖励写入本地存档失败，顶部显示结算未保存警告，并提供 `重新保存` 与 `返回大厅`，禁止静默丢失奖励。

#### `GachaPage`
* **线框结构：** 顶部为抽卡资源条，中部为扭蛋机主体和抽卡按钮，底部为最近结果与跳过演出控制区。
* **必备组件：** 当前抽卡资源展示、单抽/十连入口占位、扭蛋机展示区、结果弹出层、跳过演出按钮、最近获得记录。
* **空状态：** 若玩家没有足够的抽卡资源，中部保留扭蛋机展示，但主按钮置灰，并展示“资源不足”说明和进入 `Play` 开启对局获取资源的引导。
* **错误状态：** 若抽卡结果保存失败，必须直接展示抽卡结果内容，同时弹出错误提示，允许玩家 `重新保存结果`，避免出现结果已出但存档未落地的歧义。

#### `GalleryPage`
* **线框结构：** 左侧或上方为弹珠列表，右侧或下方为详情抽屉，底部为筛选和排序控件。
* **必备组件：** 弹珠卡片列表、稀有度筛选、属性雷达图、被动说明、碎片进度、升星按钮、已解锁/未解锁状态标识。
* **空状态：** 若只拥有初始弹珠，则列表区保留空位占位，详情区默认展示初始弹珠，并提示“通过抽卡或成长解锁更多弹珠”。
* **错误状态：** 若图鉴配置读取失败，列表区改为只显示基础弹珠占位，并提供 `重试加载图鉴` 操作。

#### `MetaTreePage`
* **线框结构：** 顶部为当前资源与页签，中部为天赋树主体，右侧或下方为节点详情面板，底部为确认区。
* **必备组件：** 记忆碎片余额、天赋树画布、节点连线、节点详情卡、升级确认按钮、重置或返回按钮。
* **空状态：** 若当前没有可分配资源，则保持天赋树可浏览，但确认按钮禁用，并明确提示下一次获取资源的来源。
* **错误状态：** 若节点升级写入失败，必须回滚本次预览分配，并展示 `重试升级` 与 `返回大厅` 操作。

#### `SettingsPage`
* **线框结构：** 顶部为设置分类页签，中部为具体设置表单，底部为恢复默认与返回按钮。
* **必备组件：** 音量滑杆、画质选项、输入偏好开关、震动反馈开关占位、恢复默认按钮、返回按钮。
* **空状态：** 若玩家从未调整过任何设置，则各项默认值直接可见，并标注“当前为推荐默认配置”。
* **错误状态：** 若设置保存失败，页面应提示“设置未写入本地”，保留当前用户输入，同时提供 `重新保存` 与 `恢复默认` 操作。

### 3.4 通用状态反馈规则 (Shared State Rules)
* **加载与空状态：** 所有首发页面都必须支持 `加载中`、`空状态` 反馈，不允许只依赖控制台或静默失败。所有空状态都应说明“为什么是空的”以及“下一步该做什么”。
* **错误处理简化：** 鉴于本游戏为“离线单人 Web MVP”，本地存储（LocalStorage / IndexedDB）极少发生网络式中断。因此对于存档写入失败等情况，不再强制各页面单独设计复杂的“回滚/重试”界面层，而是**统一采用全局轻量级 Toast 异常提示**。

## 4. 适配与安全区 (Safe Area & Adjustments)
* **移动端防误触：** 右下角的手柄操作条在纵向上必须留出底部 30px 以上的安全边距，防止 iOS 的 Home 底部横条与 Android 的手势导航栏被误触。
* **PC端按键映射：** 除了直接用鼠标拖动右侧手柄外，可以留一个补充的辅助按键：按住 `Space (空格键)` 开始自动循环充能增减，松开即发射以降低鼠标疲劳感。

## 5. 常规抽卡与图鉴界面 (Gacha & Gallery UI)
结合游戏内的“英雄弹珠”养成机制，抽卡界面需要在首发保证功能完整，在后续版本再追求更强的情绪释放。
* **物理扭蛋机视觉 (Gacha Machine)：**
  * **首发 MVP：** 以 2D/2.5D 扭蛋机功能页呈现，支持快速播完的短演出、跳过按钮与结果复盘。
  * **后续阶段：** 可升级为巨大的 3D 扭蛋机 / 柏青哥出口演出，允许更复杂的镜头与物理表演。
  * 玩家拉动右下角熟悉的手柄，投入一颗特制的抽卡球，经过一系列清脆的物理掉落，最终落到底部扭蛋出口，弹出获得的弹珠。
* **图鉴展柜 (Display Gallery)：**
  * 横向划动的玻璃展柜界面。不同的英雄弹珠（如刺客球、铅球、魔法球）漂浮在带有科技感的底座上。
  * 点击单颗弹珠，右侧（PC段）或下方（移动端）弹出抽屉式面板：
    * **雷达图：** 展示物理属性（重量、反弹力、体积）。
    * **被动技能：** 该弹珠特有的局内效果描述。
    * **碎片进度：** 如 `20/50`，满进度显示高亮的“升星 (Rank Up)”按钮。

## 6. 肉鸽核心结算与三选一 UI (Roguelite UI Details)
为确保局内流派构筑的沉浸感与顺畅度，需要精准把控三选一卡牌的具体比例。
* **构筑卡牌布局 (Three Choices Layout)：**
  * **出现时机：** 当局内完成一层，或达到阶段奖励条件时，以 `Time.timeScale = 0` 冻结游戏时间。背景采用强力毛玻璃（Blur）滤镜覆盖机台区。
  * **尺寸比例：** 横向排列 3 张长方形卡牌，每张卡牌高宽比约为 1.618 (黄金比例)。移动端时占满屏幕宽度的 90%。
* **卡牌信息层级 (Card Hierarchy)：**
  * 顶部（15%）：羁绊图标 (例如火系、动能系标志)。这里的“卡牌”具象化为**局内可放置的额外机关（钉子、高弹力柱等）**以及**不同材质和特性的弹珠**。
* **构筑卡牌布局 (Three Choices Layout)：**
  * **出现时机：** 当局内完成一个波次（Wave），或达到阶段奖励条件时，以 `Time.timeScale = 0` 冻结游戏时间。背景采用强力毛玻璃（Blur）滤镜覆盖机台区。
  * **尺寸比例：** 横向排列 3 张长方形卡牌，每张卡牌高宽比约为 1.618 (黄金比例)。移动端时占满屏幕宽度的 90%。
* **卡牌信息层级 (Card Hierarchy)：**
  * 顶部（15%）：类型图标 (例如 `弹珠` / `钉子` / `机关`)。
  * 中部（40%）：能传达物品形态的生动核心原画（如一颗沉重的铁球，或一枚带闪电特效的钉子）。
  * 底部内容（45%）：
    * 主标题（加粗，如“高频雷射钉” 或 “附魔重铅球”）。
    * 品质颜色区分（普通-白/稀有-紫/传说-金）。
    * 机制描述条（如“*增加一枚可放置的钉子：碰撞有30%机率赋予感电*” 或 “*极高的质量，下落速度极快但难以受到微反弹的影响*”）。
* **选择反馈：** 选中一张卡片后，其余两张卡片呈粒子化碎裂消失。若选中“弹珠”，则飞入右侧的弹珠切换队列；若选中“机关道具”，则立即进入 `Placement` 放置状态，玩家在机台上将其拖拽放置到位。

### 6.1 结算页信息层级 (Result Page Hierarchy)
首发 `ResultPage` 建议固定为三层信息，避免结算页承担过多运营或社交内容：

* **顶部：** 本局总分、推进到的最高波次备，不作为首发阻塞项：

* 排行榜展示位、公会入口、好友挑战入口。
* 依赖在线活动数据的赛季面板与运营弹窗。
* 超过 8 秒的长抽卡演出与不可跳过镜头。`GaragePage`：机具与配件改装系统的 UI。
*
