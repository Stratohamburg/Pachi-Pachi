# 部署与运维规范 (Deployment & Operations)

## 1. 静态资源优化
* **图集打包策略：** 通过 Texture Packer 或自动构建流，将零散图片拼合成超大图集(Atlas)，极大缩减DrawCall和HTTP请求数。
* **代码及资产压缩：** 发布包自动执行 Javascript 代码混淆、Uglify 压缩；音频统一走轻量级的 `.m4a` 或 `.ogg`，而非原无损格式。

## 2. 分包与按需加载策略
* **首屏渲染优先：** H5 游戏对启动时间极敏感，引擎基础核心层与 Loading 首屏UI必须放至默认极小的主包（Main Bundle）。
* **动态载入：** 关卡编辑器模块、以及高画质的主题大图需进行拆包隔离（Subpackage），玩家进入指定模式或具体图纸前再按需异步拉取。

## 3. 日志与性能监控
* **帧率与内存监听：** 前端在运行态需加入常态化的 FPS 探针统计以及内存泄露预警；针对低端移动设备进行自动降级（例如自动屏蔽所有发光粒子特效）。
* **业务行为打点：** 记录玩家的异常离线、结算失败率，及局内各个环节的漏斗转化埋点（用于策划后期统计关卡难度平衡性）。

## 4. 本地开发环境配置指南 (Developer Setup)
当前仓库主要承载文档与配置；以下要求用于应用工程骨架落地后的统一开发基线，确保新的程序人员拿到代码后能在 5 分钟内 Run 起来。
1. **环境依赖：** 安装 Node.js (LTS) 与 npm；当前客户端技术栈固定为 `TypeScript + Vite + PixiJS + React + Matter.js`。
2. **初始化与运行：** 
   * `npm install` 下载依赖。
  * `npm run dev` 启动 Vite 本地热更新服务器（默认 `localhost:5173`）。
3. **Editor 集成：** 推荐使用 VS Code 打开，装配 ESLint 与 Prettier 规范文件，保证所有上传的代码风格全部强制对齐一致。

## 5. CI/CD 自动化流水线 (Pipeline)
为该 Web 游戏建立标准的 GitHub Actions 构建流程：
* **Push 触发 (Test & Lint)：**
  * 在触发任意至 `develop` 或 `main` 的 PR/Push 操作时，自动执行 `npm run lint` 和单元测试（例如测试核心算分算法函数），未通过不准许 Merge。
* **分发环境构建 (Build)：**
  * 测试通过之后，自动执行 `npm run build` 生成静态前端资源的 `dist/` 文件夹。
* **发布至 CDN (Deploy)：**
  * 流水线将 `dist/` 中自带 MD5 摘要后缀的 HTML/JS/PNG 文件通过命令行直接上传分发发布至云原生的对象存储桶（例如 AWS S3 / 阿里云 OSS）。
  * 自动刷新边缘节点 CDN 缓存。

## 6. 在线能力说明 (Deferred Services)
首发版本按纯静态前端 + 本地持久化方案部署，不要求独立游戏服务端。云存档、排行榜、公开 UGC 与防作弊能力属于后续阶段，届时再补充对应的后端部署与运维方案。
